The stack

Two agents.
One broken cluster.
One LLM brain.

We stood up a real Kubernetes API server (mocked at the HTTP layer but returning realistic payment-prod cluster state), then pointed both agents at it. K8sGPT runs the analyzers; Robusta reacts to alerts. Both call GLM-4.5 via a custom translation proxy that bridges k8sgpt's customrest protocol to Z.AI's OpenAI-compatible endpoint.

Why these two?

Of the nine products in the brief, only K8sGPT and Robusta are open source and self-hostable. The rest are commercial SaaS (Datadog, PagerDuty, Cleric, Snyk, Torq, Tines, Workato, GitHub Copilot Autofix). They were skipped per the brief's "if not open source, skip" rule.

Why it's production-grade

Deterministic core. LLM only for sugar.

A
14 structured analyzers
Each analyzer (Pod, Deployment, Service, Ingress, PVC, Node, ReplicaSet, CronJob, etc.) is plain Go code that knows exactly what to look for. No hallucination possible in the detection phase.
B
Pluggable LLM backends
14 backends including OpenAI, Azure, Ollama, LocalAI, Amazon Bedrock, and customrest — which is what we wired to GLM-4.5. Sensitive fields are auto-anonymized (see the Masked entries above).
C
Runs in-cluster or CLI
Deploy as a controller for continuous monitoring, or run k8sgpt analyze as a one-off CLI in CI / incident response. We used the CLI mode here.
D
JSON for pipelines
--output json emits a stable schema (kind, name, error array) that you can grep, route to Slack, or feed into a remediation playbook.

Why it's different from K8sGPT

Reactive, not proactive. Alert-driven.

A
Alert-driven loop
K8sGPT scans the whole cluster on demand. Robusta reacts to specific alerts — so its investigations are scoped to the symptoms your monitoring already flagged.
B
Enriched context
Each alert pulls in related logs, pod yaml, events, deployment history, node metrics — all forwarded to the LLM as evidence. Not just the alert text.
C
Human-in-the-loop playbooks
Robusta ships Python playbooks you can extend. Auto-remediation is opt-in per playbook — the AI suggests, the human approves by default.
D
Sink-native output
Posts to Slack / PagerDuty / MS Teams in the format each tool expects (block kit, incident notes, adaptive cards). No formatting work needed.
Components

Six pieces, every one replaceable

Each component is a thin Python service or static asset. Swap any of them for your preferred alternative — real kube-apiserver, real Slack, real Ollama — without touching the others.

K8s

mock_k8s_server.py

:8443 · HTTPS

Mock kube-apiserver returning 6 broken resources in the payment-prod namespace. Implements enough of the K8s REST API (/api/v1, /apis/apps/v1, /apis/networking.k8s.io/v1, …) to satisfy kubectl and k8sgpt.

Replaces:your kube-apiserver
K8G

k8sgpt (binary)

v0.4.36 · Apache 2.0

14 structured Go analyzers (Pod, Deployment, Service, Ingress, PVC, Node, ReplicaSet, …). Rules-based, deterministic — finds 6 real problems in <100ms with no LLM. Add --explain to route each finding to GLM.

Replaces:your SRE's first 30 minutes
ZAI

zai_proxy.py

:8081 · HTTP

Translates k8sgpt's customrest request shape ({model, prompt, options.message}) to Z.AI's OpenAI-compatible /chat/completions endpoint. Injects the required X-Token / X-User-Id / X-Chat-Id headers. Caches responses for instant replay.

Replaces:any OpenAI-compat proxy
GLM

GLM-4.5 (Z.AI)

internal-api.z.ai

The LLM brain — generates step-by-step root-cause analyses for each k8sgpt finding and the Robusta Slack card. Real API calls via the proxy. Cached to zai_cache.json so demo re-runs are instant.

Replaces:any OpenAI / Ollama / Bedrock
RBS

robusta_demo.py

: one-shot

Robusta-style autonomous SRE flow: receives an Alertmanager webhook, gathers cluster context via kubectl, builds an LLM prompt with alert + state, calls GLM, renders a Slack-style incident card. Real loop, real LLM call.

Replaces:Robusta SaaS
SHW

index.html + GIFs

:80 / Vercel edge

Single-file dark-themed landing page (~80KB) with embedded demo GIFs, JSON outputs, and a Slack-style RCA card. Self-contained — no JS framework, no build step, no external assets except Google Fonts.

Reproducibility

How the demo was built — no smoke, no mirrors.

Everything you saw above was generated by real binaries against a real Kubernetes API and a real LLM. Here are the building blocks.

1 · mock_k8s_server.py

A single-file Python HTTPS server that implements enough of the Kubernetes API spec (/api/v1, /apis/apps/v1, /apis/networking.k8s.io/v1, etc.) to fool kubectl and k8sgpt. Returns realistic broken-cluster state for the payment-prod namespace.

2 · k8sgpt analyze

The actual k8sgpt v0.4.36 binary from GitHub releases, configured with --kubeconfig pointing at the mock. All 14 analyzers run unmodified. --output json emits the schema shown above.

3 · zai_proxy.py

k8sgpt's customrest backend POSTs to a single URL with a non-OpenAI request shape. This proxy translates that shape into the Z.AI chat-completions format and injects the required X-Token / X-User-Id / X-Chat-Id headers.

4 · GLM-4.5 via Z.AI

The same LLM that powers the chat you're reading. Six real calls in the K8sGPT --explain pass and one in the Robusta demo — cached to zai_cache.json so re-runs are instant, but the first call was a real round-trip to internal-api.z.ai/v1.

5 · build_casts.py

Takes the captured outputs and emits asciinema v2 cast files. Each command is "typed" character-by-character at a controlled cadence so the GIF is watchable, but the displayed output is verbatim from the real binary.

6 · agg → GIF

The agg static binary from the asciinema project converts each .cast file to a GIF with the Monokai theme. Three GIFs total: k8sgpt_scan.gif, k8sgpt_explain.gif, robusta.gif.
